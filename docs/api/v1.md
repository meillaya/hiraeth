# Catalog API v1

Read-only JSON access to the curated catalog. The browser catalog and this API
serialize the same typed projections, so a book rendered at `/books/:slug` and a
book returned by `/api/v1/books/:slug` describe the same record.

Base path: `/api/v1`. The machine-readable contract is served at
`/api/v1/openapi.json` and is generated from the controller operations and
schema modules in `lib/hiraeth_web/api/`.

## Endpoints

| Method | Path | Returns |
|---|---|---|
| GET | `/api/v1/books` | Page of books, with filters |
| GET | `/api/v1/books/:slug` | One book, by work slug or edition slug |
| GET | `/api/v1/editions/:slug` | One edition, with source provenance |
| GET | `/api/v1/publishers` | Page of publishers |
| GET | `/api/v1/publishers/:slug` | One publisher, with its books and facets |
| GET | `/api/v1/series` | Page of series with preview books |
| GET | `/api/v1/series/:slug` | One series, with member books |
| GET | `/api/v1/contributors` | Page of contributors |
| GET | `/api/v1/contributors/:slug` | One contributor, with books |
| GET | `/api/v1/openapi.json` | OpenAPI 3.0 document |

Every endpoint is a `GET`. There is no write, auth, or account surface.

## Response envelopes

A collection response has `data` and `meta`:

```json
{
  "data": [{ "id": "…", "slug": "the-employees", "title": "The Employees" }],
  "meta": { "page": 1, "page_size": 24, "total_count": 8776, "total_pages": 366 }
}
```

A single-resource response has `data` only:

```json
{ "data": { "id": "…", "slug": "the-employees", "title": "The Employees" } }
```

Failures use one envelope:

```json
{
  "error": {
    "code": "invalid_parameter",
    "message": "page_size must be between 1 and 100",
    "details": {}
  }
}
```

`code` is one of `not_found`, `invalid_parameter`, or `internal_error`.
`details` is always an object, empty unless the error names a specific field.

## Pagination

`page` starts at 1. `page_size` is 1 to 100 and defaults to 24. `page` is capped
at 10,000 before any SQL offset is built, so a malformed page number cannot
overflow the database integer encoder. A page number beyond the last page is
clamped to the last page, and `meta.page` reports the page actually served.

## Book filters

| Parameter | Meaning |
|---|---|
| `q` | Free text across title, subtitle, publisher, contributor, series, and ISBN |
| `publisher` | Publisher slug or name |
| `role` | Contributor role, `author` or `translator` |
| `contributor` | Contributor slug or name |
| `format` | Edition format such as `paperback` |
| `language` | Edition language code |
| `subject` | Subject term |
| `series` | Series slug or title |
| `year` | Publication year, integer |
| `sort` | `newest`, `title`, `author`, or `recently_added` |

`sort=newest` orders by publication date, newest first, with title and slug as
tie breakers. `title` orders by lowercased work title. `author` orders by the
first contributor name. `recently_added` orders by the newest source record
import time. The browser's home page uses `recently_added`; the browse page uses
`newest`.

Unknown query parameters are ignored. A non-string shape such as `?q[a]=b` is
dropped at the parameter boundary instead of raising.

## Covers and provenance

A `cover` object appears only when the catalog has a local, publicly renderable
cached file. A cover row whose file is not cached yet is omitted, so `cover` is
`null` rather than an object with a null `public_url`. `source_url` is the
provider URL and exists for attribution, not for hotlinking.

`source` and `sources` expose `provider`, `source_type`, `source_uri`,
`source_identity`, `license_note`, and `imported_at`. Internal row identifiers
(`source_record_id`, `import_run_id`), cache file paths, and field-level
provenance maps are not exposed.

Fields the source did not supply appear in `missing_fields` as
`{"field_name": "reason"}`, matching the browser's gap states. The API never
fills a gap with a guess.

## Versioning

`v1` accepts additive changes only: new fields, new optional parameters, new
endpoints under `/api/v1`. Removing or renaming a field, changing a type,
changing an error code, or changing pagination semantics requires `/api/v2`.
A removed field gets a deprecation note in this document for at least one minor
release before removal.

## Examples

```bash
curl -s 'https://hiraeth-web-production.up.railway.app/api/v1/books?q=fitzcarraldo&page_size=2'
curl -s 'https://hiraeth-web-production.up.railway.app/api/v1/books/the-employees'
curl -s 'https://hiraeth-web-production.up.railway.app/api/v1/publishers/new-directions'
curl -s 'https://hiraeth-web-production.up.railway.app/api/v1/openapi.json'
```

## Contract enforcement

The test suite validates every endpoint response against the served OpenAPI
schema, and a separate contract test builds the document and asserts that every
route has an operation id, a success schema, and a 4xx response. Adding a
serializer field without updating `HiraethWeb.Api.V1.Schemas` fails the suite.

Known gaps, deliberately not hidden:

- No rate limiting. A public deployment should put a limit in front of the API
  or add a plug-level throttle before announcing it broadly.
- No `ETag` or `Cache-Control` on responses. The read model caches for 30
  seconds in process, but HTTP clients see no cache metadata.
- No CORS policy. Browsers can call the API only same-origin. A cross-origin
  consumer needs an explicit allowed origin list, not a wildcard.
